# 碎碎念小模型：做什么、怎么训（v0.1 草案）

> 状态：草案，未开工 · 依赖：「今日」SPEC · 离线评测：`scripts/murmur_eval/`

## 0. 定位

手机上常驻一个约 0.6B 的小模型。每写一条碎碎念，它在后台读一遍，把这段自由的文字变成几个**固定的标签**。

它要解决两件事：

1. **回头看见自己**：给以后的回顾、统计、搜索提供原料，比如"这个月游泳 5 次"、"偏头痛 4 次"、"我做过的菜"
2. **别漏掉要办的事**：粗筛出可能要处理的碎碎念，交给云端确认（§4.1）

**原则**

- 离线、不联网、不需要配置模型。打标签只是锦上添花，关掉以后「今日」照样完整可用
- 打出的标签是**派生数据**：不写进 journal 文件，存在可以重建的索引里。换了模型就在后台重新打一遍
- 不评判。模型可以看出"这周提到 3 次累"，但界面上不说"你这周状态很差"，也不制造愧疚
- 能用代码做的不交给模型：日期换算、数数、统计、去重都用代码
- 抽取只能摘原文：模型给出的人名、菜名、书名必须是原文里的字，不是原文的一律丢掉（§3.4）

## 1. 小模型做什么、不做什么

| 做 | 不做（交给谁） |
|---|---|
| 判断有没有要办的事、要查的问题（宁可多报） | 确认、抽取时间和参数、执行（云端 agent，用户点了才执行） |
| 一条碎碎念的主要情绪 | 长期心理判断（不做） |
| 属于生活的哪些方面 | 写周报、写总结这类长文（云端或模板） |
| 摘出提到的具体东西：吃的、书影音、人、地点、身体状况、运动、花销 | 回答问题、讲知识（云端） |
| 标出值得回看的高光时刻 | 认物种、看照片（BioCLIP 等专门模型） |
| | 换算日期、统计次数（代码） |

## 2. 一个普通人会写什么

依据：作者自己 2026-05～10 的 244 条有文字的碎碎念，加上对其他人群的设想。

- **写法**：从一个词（"好多人呀"）到几百字的长段；诗句和自己写的俳句；emoji；语音转写出来没有标点；繁体字
- **内容**：吃了什么、做了什么菜；身体（偏头痛、牙痛、拔智齿）；运动（游泳几米、健身）；读书、看剧、听歌；天气和季节；家人朋友；工作和裁员焦虑；对人生、社会、AI 的感慨；偶尔的计划和问题
- **要办的事很少**：244 条里只有 16 条（约 7%），而且常常藏在一段感慨的中间
- **问号很多，但大多是反问**："如何激发好奇心？"、"会不会有生之年看到……"

不同人群差别很大，训练数据要覆盖：学生、上班族、带娃的父母、退休老人、体力劳动者、自由职业。不能只照着作者一个人写。

## 3. 输出格式

一次读入，一行输出，用 GBNF 语法约束，保证格式一定合法：

```
意图|情绪|方面|提及|高光
```

例子：

```
今天起床继续偏头痛了，不知道啥原因
→ 记录|难受|身体|症状:偏头痛|否

今天 34 分钟游了800米，感觉还是很不错的，游泳技能有点进步
→ 记录|满足|运动|运动:游泳;数量:800米|是

止痛药还是牛，感谢布洛芬，这段时间没痛了，忍一忍，感觉晚上睡觉前得吃一颗
→ 待办|满足|身体|药:布洛芬|否

明天中午来一个烂肉豇豆，晚上来一个葱姜蟹，有点期待明天吃什么了哈哈哈
→ 待办|期待|吃喝|吃喝:烂肉豇豆;吃喝:葱姜蟹|否

这是什么花呀，感觉像是喇叭花
→ 查询|好奇|自然|植物:喇叭花|否

人只是被塑造的产物，多少所爱所恨真是自我的选择吗？
→ 记录|低落|想法|无|否
```

### 3.1 意图（三选一）

| 值 | 定义 |
|---|---|
| 记录 | 发生的事、感受、观点、感慨、愿望、已经做完的事。**默认值** |
| 待办 | 自己接下来要做的具体的事："明天、今晚、得、记得、准备"，或者东西用完了要补 |
| 查询 | 真的想知道答案的具体问题：认东西、问做法、问事实 |

本地这一步**要召回率**：拿不准就报"待办"或"查询"，由云端确认。反问、感慨、愿望（"希望……"、"有机会试试"）都算记录，这是训练数据的重点。

### 3.2 情绪（单选，取最主要的）

| 积极 | 中性 | 消极 |
|---|---|---|
| 开心、满足、感动、期待 | 平静、好奇 | 疲惫、低落、焦虑、烦躁、生气、难受 |

- "难受"专指身体不舒服
- 讲道理、发表观点，没有明显情绪的，算平静
- 混合情绪取写到最后、写得最重的那一种
- 界面上只用三档（积极、平淡、消极）和颜色，不把具体的词展示成诊断

### 3.3 方面（1～2 个）

吃喝 · 身体 · 运动 · 工作 · 学习阅读 · 影音娱乐 · 家人 · 朋友社交 · 伴侣 · 孩子 · 宠物 · 自然天气 · 出行 · 居家 · 钱 · 创作爱好 · 想法

这一层和旧日记的"主题"（日常片刻、念头与好奇……）不同。旧主题是文艺的分类，这里是**生活的方面**，用来做统计。界面上要不要显示、怎么起名，另外再定。

### 3.4 提及（抽取，0～5 个）

格式是 `类型:原文`，多个用 `;` 分隔，没有就写 `无`。

| 类型 | 例子 | 回顾里的用处 |
|---|---|---|
| 吃喝 | 宫保虾球、明前茶 | "我做过的菜"、吃了什么 |
| 书影 | 《昨日的美食》、人间鲁迅 | 这个月读了、看了什么 |
| 音乐 | 曾轶可、阳台民谣 | 和"听过的歌"打通 |
| 人 | 二姨、奎、小王 | 提到最多的人 |
| 地点 | 方所、松潘、图书馆 | 去过哪里 |
| 症状 | 偏头痛、牙痛 | 身体记录（不给医疗建议） |
| 药 | 布洛芬 | 同上 |
| 运动 | 游泳、哈克深蹲 | 运动次数 |
| 数量 | 800米、34分钟、68.5公斤 | 运动量、体重 |
| 花销 | 一百二 | 花了多少（只记录，不评价） |
| 植物、动物 | 绣球花、红头长尾山雀 | 和物种图鉴打通 |

**校验**：每一项的"原文"必须能在碎碎念里原样找到。找不到就丢掉，从规则上杜绝模型编造。

### 3.5 高光（是/否）

第一次、做成了、有进步、特别的时刻："第一次做饼"、"游了800米有进步"、"终于拔了智齿"。用来做月度、年度回顾。要从严判断，宁可少标。

## 4. 和产品的对应

| 标签 | 用在哪里 |
|---|---|
| 意图=待办/查询 | 打开"智能建议"开关后（默认关闭）发给云端确认。确认是要办的，碎碎念下面出现一个提示（"要我明天中午提醒你吗？"），用户点了才执行。云端说不是，就什么都不显示 |
| 情绪 | 日历上每天一个心情色；回顾里一条心情曲线 |
| 方面、提及 | 回顾："十月游泳 5 次、读了 3 本书"；合集："我做过的菜"；搜索：按人、按菜、按地点 |
| 症状 | "偏头痛：5/5、6/15、6/25、7/25"，只列出事实 |
| 高光 | 月度、年度的高光时刻 |

### 4.1 云端确认

只有意图不是"记录"的碎碎念才会发出去。用作者的真实数据粗估，提示词版本大约发出 40%，微调后目标是 20% 以内。发出去的只有这一条碎碎念的文字，不带位置和照片。

## 5. 训练数据

### 5.1 标注规范是核心

§3 就是标注规范。生成数据、给数据打标签、人工抽查，用的都是同一份规范。规范里每一条都要配正例和反例，特别是这些难例：

- 反问和感慨（问号多，但不是在问）
- 愿望和计划的区别（"有机会试试" 和 "明天做"）
- 已经做完的事（"做了"、"买了"、"终于交了"）
- 要办的事藏在长段落中间
- 诗句、引文：情绪看写的人，不看诗本身
- 观点里带情绪（"都是垃圾"算烦躁还是平静）
- 混合情绪

### 5.2 数据从哪里来

| 用途 | 来源 | 数量 |
|---|---|---|
| 训练 | 大模型合成：按人群 × 写法 × 内容 × 意图组合着写，再由大模型按规范打标签 | 约 3000 条 |
| 开发集（调参数用） | 同上，另外生成 | 约 300 条 |
| 测试集（只测，不训，也不拿来调提示词） | 作者的真实碎碎念（`~/.journal`，244 条），人工确认标签 | 244 条 |
| 第二测试集 | 「今日」里新写的碎碎念，积累几周之后 | 以后再说 |

- **比例**：真实情况里要办的只占约 7%，训练时提高到约 25%，让模型见得够多
- **质量**：标签用两遍独立标注，两次不一致的丢掉或交给人看。每一类人工抽查 50 条
- **隐私**：作者的真实碎碎念**不**作为训练数据，也不发给云端去模仿风格。合成数据只参考 §2 里总结出的写法特征

### 5.3 训练

- 基座：Qwen3-0.6B（也试 1.7B 作为上限参照，不上手机）
- 方法：MLX-LM 做 LoRA，在 M3 16GB 上训练
- 微调以后，系统提示可以缩到一两句话，每次读入的内容更少，速度更快
- 导出：合并 LoRA → GGUF Q8_0（约 640MB）→ 手机上用 llama.cpp 运行

## 6. 评测和上线门槛

所有指标都在真实测试集上算。基线是 2026-10-15 只改提示词时的成绩。

| 字段 | 指标 | 基线 | 目标 |
|---|---|---|---|
| 意图 | 待办+查询的召回率 | 100%（但发出 40%） | ≥ 95% 召回，发出 ≤ 20% |
| 情绪 | 三档准确率 | 68% | ≥ 80%，消极的召回率 ≥ 80% |
| 方面 | micro-F1 | 未测（旧主题命中率 34%） | ≥ 0.75 |
| 提及 | 精确率 / 召回率 | 定性很差 | ≥ 85% / ≥ 70%，编造率 0（靠校验） |
| 高光 | 精确率 | 未测 | ≥ 80% |
| 格式 | 合法率 | 100% | 100% |
| 速度 | 手机上 P50 / P95 | 未测 | ≤ 1s / ≤ 2s，在后台运行 |
| 内存 | 峰值 | 未测 | ≤ 800MB，用完就释放 |

### 6.1 第一轮结果（2026-10-15）

做法：`scripts/murmur_train/` 下 809 条手写合成数据，加上 400 条拼接的长段落（`build.py`），用 MLX 做 LoRA（rank 16，lr 5e-5，全部层），在 M3 上 500 步约 12 分钟。取第 300 步的检查点，合并后导出为 GGUF Q8_0（639MB），用 llama.cpp 加 GBNF 语法、CPU 4 线程评测。测试集是 244 条真实碎碎念。

| 字段 | 只改提示词 | 微调 r4_300 | 目标 |
|---|---|---|---|
| 意图 | AUC 0.87；召回 100% 时送出 40% | AUC 0.963；召回 100% 时送出 24%（P(记录) 阈值 0.05） | 发出 ≤ 20% |
| 情绪 | 三档 68% | 三档 66%，**正负颠倒 3%**，消极召回 87% | 三档 ≥ 80% |
| 方面 | 旧主题命中 34% | F1 0.74 | 0.75 |
| 提及 | 很差 | P 59% / R 70%，编造 0 | 85% / 70% |
| 高光 | — | P 60% / R 38%（只有 8 条） | P ≥ 80% |
| 格式 | 100% | 100%（GBNF） | 100% |
| 速度（Mac CPU 4 线程） | — | 中位 173ms，P95 419ms | 手机待测 |

结论和问题：

- 三档情绪没有提升，错误大多在"平静"和"满足"之间，两种都说得通。真正有害的正负颠倒只有 3%。界面上可以把平静、满足都显示成浅色，或者情绪只区分"积极"和"消极"
- 提及的错误大多是边界问题（"西班牙插画"算不算书影）。要提升，得把规范写得更细，并配更多例子
- 测试集只有 21 条要办，不同检查点之间波动很大，指标不稳定。需要更多真实数据（「今日」里新写的碎碎念）
- 我看过测试集的错误以后，按**类型**补了训练数据（认东西的问题、当天的打算、高光、长段落），没有照抄原句，但仍然有一定的过拟合风险

### 6.2 第二轮（2026-10-15）

改动：

- **挑检查点不再看测试集**：新增 55 条长段落开发集 `dev/dev_long.tsv`，`select_ckpt.py` 在开发集上给每个检查点打分。真实测试集每一轮只在最后打一次分
- **情绪规范**：写清了满足和平静、开心和满足、低落和平静的分界；按新规则统一了 18 条训练标注、2 条测试标注
- **数据**：再补约 70 条长段落，合成数据一共 877 条（加 400 条拼接）
- **权重平均**：把第 300～500 步的 5 个检查点取平均（soup）。开发集得分 0.835，不低于最好的单个检查点，按事先定好的规则采用平均版
- **意图加一组关键词规则**：模型 P(非记录) ≥ 0.02，**或者**命中通用关键词（明天、记得、准备、怎么、什么……呢），就送云端确认

真实测试集结果（GGUF Q8_0，llama.cpp + GBNF，CPU 4 线程）：

| 字段 | 第一轮 r4_300（看测试集挑的，偏乐观） | 第二轮 soup5 | 目标 |
|---|---|---|---|
| 意图 | 召回 100% 时送出 24% | **模型或规则：召回 95%，送出 19%** | ≥ 95% / ≤ 20% ✓ |
| 情绪 | 三档 66%，颠倒 3% | 三档 **72%**，颠倒 **2%**，消极召回 74% | 80% |
| 方面 | F1 0.74 | F1 **0.75** | 0.75 ✓ |
| 提及 | F1 0.64 | F1 **0.67**（P 64% / R 71%） | P 85% |
| 高光 | P 60% / R 38% | **P 100%** / R 38% | P ≥ 80% ✓ |
| 速度 | 中位 173ms | 中位 185ms，P95 459ms | 手机待测 |

模型文件：`~/models/qwen3/murmur-0.6b-soup5-Q8_0.gguf`

### 6.3 真机测试（2026-10-15，小米 15 Ultra，骁龙 8 至尊版，16GB）

llama.cpp 用 NDK r27 交叉编译（`-DGGML_CPU_ARM_ARCH=armv8.7a+dotprod+i8mm`），在手机上起 llama-server，用 adb forward 把 244 条真实碎碎念逐条发过去。

- **准确率**：Q8_0 在手机上的结果和 Mac 上完全一致
- **线程**：2 个线程就够了（读入约 520 token/s，生成约 95 token/s）。4～6 个线程提升很少，后台运行用 2 个
- **内存的坑**：
  - llama-server 默认开着提示缓存（`--cache-ram` 8GB），跑完 244 条涨到 2.8GB。要设 `--cache-ram 0`
  - 用 mmap 加载时，权重为了 i8mm 会重排一份，加上文件映射，总共约 1.43GB。用 `--load-mode none` 只留一份
- **量化**：只有 Q8_0 和 Q4_0 能用上 i8mm 的重排加速，K 系列量化（Q4_K_M、Q5_K_M、Q6_K）慢 2～3 倍

| 版本 | 文件 | 峰值内存 | 读入 / 生成（token/s，2 线程） | 三档情绪 | 提及 F1 | 要办：模型或规则 |
|---|---|---|---|---|---|---|
| Q8_0 | 639MB | ~970MB | 454 / 99 | 72% | 0.67 | 阈值 0.01：召回 95%，送出 23% |
| **Q4_0** | **382MB** | **744MB** | 274 / 62 | 75% | 0.65 | 阈值 0.005：召回 100%，送出 30%；阈值 0.02：召回 90%，送出 20% |
| Q5_K_M | 444MB | 803MB | 168 / 36 | 73% | 0.67 | — |
| Q4_K_M | 397MB | 760MB | 163 / 49 | 74% | 0.61 | — |

端到端延迟（含 GBNF，手机连续跑了上千条、电池 37～38°C 时测的，实际单条使用会更快）：Q8_0 中位 224～315ms，Q4_0 中位 373ms，P95 935ms。模型加载约 1.7 秒。

**已定 Q4_0**（2026-10-15 作者确认）：内存在 800MB 以内，准确率和 Q8_0 差不多。如果更在意速度，用 Q8_0。测试集只有 21 条要办，1 条就是 5%，两个版本在意图上的差别在噪声范围内。

## 7. 待定

1. §3.2 情绪词、§3.3 方面列表、§3.4 提及类型：这几份清单要作者确认
2. 要不要识别强烈的痛苦信号（比如自伤念头）。如果要做，只温和地显示求助资源，不报警、不评判；做不好宁可不做
3. 合成数据用哪个大模型生成
4. 语音碎碎念：先转写再走同一个模型，还是以后用 SenseVoice 直接从声音里判断情绪
5. 时间：新功能要等 2026-10-19 左右「今日」试用周的反馈之后再接进 App；数据和训练可以先做
